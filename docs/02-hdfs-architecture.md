# Core Architecture: HDFS

The **Hadoop Distributed File System (HDFS)** is a highly fault-tolerant distributed file system. It operates under the "Write Once, Read Many" (WORM) paradigm and was designed to host extremely large files.

## The Main Actors

### NameNode (The Master)
The brain of the operation. It keeps in memory (RAM) the map of the entire file system, coordinating on which nodes each file block is stored. It neither processes nor stores data directly, only **metadata**.

### DataNodes (The Workers)
The cluster's workforce. Dozens, hundreds, or thousands of nodes that store the actual data blocks on their local hard drives. They continuously communicate with the NameNode through *Heartbeats*.

## Block Engineering and Protection

- **128 MB Blocks:** HDFS uses huge blocks to minimize seek time on mechanical HDDs and maximize continuous reading of large data slices at once.
- **Replication:** By default, each block generated by HDFS is copied 3 times on different machines to prevent data loss in case of physical failures.
- **Rack Awareness:** Hadoop is smart enough not to leave all copies on the same physical network rack, spreading nodes to ensure power and connectivity resilience in the datacenter.

## System Configuration Files

The official Apache Hadoop documentation distributes configurations across essential XML files (typically located in `/etc/hadoop/`):

- **`core-site.xml`**: General system configurations, such as the HDFS local host address (e.g., `fs.defaultFS = hdfs://localhost:9000`).
- **`hdfs-site.xml`**: HDFS-specific configurations, such as the replication factor (e.g., `dfs.replication = 3`).
- **`mapred-site.xml`**: MapReduce framework configurations.
- **`yarn-site.xml`**: YARN resource manager configurations.
- **`hadoop-env.sh`**: Environment variable configurations.

In our Docker environment, these configurations are pre-established and files like `start-hdfs.sh` and `init-datanode.sh` are responsible for initializing and formatting the main node's disk automatically when the containers start.

## 🧪 Hands-On

See the HDFS architecture working live:

1. **Access the NameNode UI** — Open http://localhost:9870. You're looking at the "brain" that manages all cluster metadata.
2. **Explore the DataNodes** — In the NameNode menu, click on **Datanodes**. See the 3 live DataNodes, with their disks and blocks. This is the HDFS "workforce".
3. **Root CLI** — In the terminal:
   ```bash
   docker exec -it namenode hdfs dfs -ls /
   ```
   This command lists the HDFS root, just like `ls` on Linux, but distributed.
4. **See replication** — Run the notebook `notebooks/01_handle_hdfs.ipynb` in VS Code. It uploads a file to HDFS. Then, go back to the NameNode UI and see the replicated blocks.
5. **Understand block size** — In the UI, click on a file you uploaded. HDFS displays how many **128 MB** blocks it was fragmented into.
